# 分类决策树 — 每页每图怎么处理

## 铁律

- 决策标记写进大纲、经用户确认后才生效；执行中发现不符 → 回大纲改标记重新确认，不悄悄改
- **继承优先**：自查做得再好不如不画——位图/XML 拷贝从根上免疫"画歪"；重绘是例外，要给理由
- 拿不准归哪类 → 停下来问用户

## 页面级（判据只有一条：结构是否承载含义）

| 标记 | 用户语言 | 判据 | 实战证据 |
|---|---|---|---|
| strict | 严格按原稿布局重画 | 把两个块换位置/合并/拆开，语义就变：架构图、流程图、泳道图、拓扑图 | 某项目 4 张架构页经用户两轮逐块纠偏才定稿——用户会逐块校对这类页 |
| free | 只搬内容，排版我发挥 | 换任何布局不损含义：列表、优势罗列、价值总结、案例页 | 某项目 7 张丑页全部属此类，重排后一次过 |
| delete | 这页不要 | 用户点名 / 真空页 | ⚠️ 判空页必须查 graphicFrame/SmartArt（文字不进普通提取），曾误删含 SmartArt 的整页 |

## 图级（三档位 + 特判）

| 档位 | 用户语言 | 适用 | 判据 / 教训 |
|---|---|---|---|
| bitmap | 直接用原稿图片 | UI 截图、证书、复杂技术架构图、案例复杂图 | 第一轮重绘的复杂图全部被用户回退："复杂图一律直接继承"。判据：形状 >30、像素级细节、AI 画不出来 |
| xml | 原样搬原稿图形（保持可编辑） | **复杂逻辑图/嵌套组拓扑的默认动作**：架构图、界面拼贴页、嵌套组带缩放变换的图 | 工具 `graft_deck.py`（deepcopy+图片按 sha1 重挂+字体强制+--swap-theme）；"继承优先"是铁律，重画要给理由。⚠️ 仅当原稿形状用显式 srgbClr：schemeClr/主题色引用会被新主题污染（拿不准就 --swap-theme） |
| redraw | 重画成可编辑图形 | 结构清晰可数的简单图：资源树、简单流程链、环图 | ⚠️ **图是啥比大纲标注说了算**——有先例大纲标"重绘"、目检是 UI 截图，改继承。SmartArt 重画前必查三层证据（gotcha #28：数据模型 vs 渲染缓存 vs LO 回退渲染，以哪层为准逐页判断） |

**特判流程**：任何 redraw 决定 → 先 Read 原稿图亲眼确认 → OCR 对账文字清单（见 self-check.md）→ 写进大纲存疑图清单请用户拍板。

## 元素级（所有页通用，继承页不许豁免）

继承图也要原生包装壳：导语、卡片、图注、相框、编号徽章。**图不动，壳必须可编辑**——否则继承页退化成贴图页，违背"原生可编辑"承诺。

## 自由发挥 = 排版自由、论点保真

"自由"的是形式，不是理解。自由发挥页仍必须：

1. **先找原稿的分组信号**：重排前扫原稿竖线/色带/框线/缩进/图标归属区间——作者的语义结构有显式信号（先例：行业标签旁竖线的 y 区间=客户 logo 归属，程序聚类猜就是错的，被打回）。找不到信号→封闭式问用户，**禁止程序聚类替代语义**
2. **大纲意图句**："这页在说什么"一句大白话（例："三类运维痛点，逼着平台必须做开放"），经用户确认
3. **布局编码论点**，从论点选页型（页型库见 design-system.md）：
   - 因果/递进 → 要求语带 + 结果卡 / 箭头链
   - 分层依赖 → 层带 + 层间下箭头
   - 总分结构 → 中心放射
   - 并列枚举 → 卡片网格（有分类加类目分组带）
   - 供给/支撑 → 供数节点 + 分配扇形
   - 流程 → 步骤链 / 泳道
4. 反例警示：一页"现状痛点 → 因此需要 X"摆成三个平铺卡片——文字审计全过，论点死了。校验脚本只能拦"文字在场"，拦不了"论点在场"；论点对不对的唯一保险是意图句被用户确认过。
