# 自查体系 — 机器对账 + 渲染自查

## 出发点（真实教训）

重建者手里只有文字提取——空间关系、块归属、连线在提取时丢失，凭推测补空；环境无渲染器看不见成品。结果是：架构图画歪靠用户逐块纠偏，一轮整批返工。本体系的目标：**机器对账拦截"内容错/关系错/漏字错"，渲染自查拦截"意思错/渲染层错"，把用户的检查从"盯图细读"降为"查表扫描"**。其他用户不一定有那个眼神，不能指望。

## 五件套（按顺序执行，全部可自动化）

| # | 机制 | 做法 | 拦得住哪类错 |
|---|---|---|---|
| 1 | 重绘前必读原图 | 提取出的原稿图直接 Read（看图），照图写规格；禁止只凭文字提取重建 | 源头错：标"重绘"实为截图、清单项数不符、错别字起点 |
| 2 | 原稿结构清单 | `structure_diff.py slide --mode-extract` 从原稿页读出块数/分带/连线数/文本集，作为照画页的规格书 | 凭推测补空本身 |
| 3 | 结构对账 | 重建后 `structure_diff.py slide` 比对：总块数、分带数、每带块数、原稿文本命中率 | 块放错层/列、层级归属错、漏画连线 |
| 4 | OCR 对账 | `structure_diff.py ocr --image 原稿图.png --dst 成品.pptx --dst-slide N`：原稿图文字清单必须在成品页命中 | 重绘页错别字、漏项 |
| 5 | 继承图哈希校验 | 成品内嵌图 sha1 == 提取图 sha1（inventory.py 已记 sha1，交付前复核） | 继承图被错版本顶替 |

## 校验三件套（每批构建后 + 交付前全量回归）

| 脚本 | 拦什么 | 全绿标准 |
|---|---|---|
| check_geometry.py | 形状越界 + 文本框交叠 | 越界 0 / 交叠 0 |
| check_overflow.py | 文字溢出启发式（高/宽两向） | 旗标 0 |
| check_text.py | 大纲 vs 成品文本完整性（逐页子串审计） | 总缺失 0 |

三者全绿是交付前置条件；任一非零 → 修复 → 重跑（改一批回归一批）。

## 渲染自查（第四道闸，有 LibreOffice 就必须做）

环境检查别信旧结论，每次实测 `sudo -n whoami`；无 soffice 时先装（`apt install libreoffice-impress`，有本地离线 deb 缓存优先用缓存）。三步走（visual_check.py）：

| 步骤 | 适用页 | 做法 | 通过标准 |
|---|---|---|---|
| render | 全部页 | `visual_check.py render 成品.pptx` | 全页出图，无空 PDF（脚本已内置空输出拦截） |
| diff | **整页沿用页** | `visual_check.py diff 原稿 成品 --pages …` | 差异 ≤6%（字体替换文字回流属正常波动）；超标先看热区图定位再判 |
| sbs | **重画/重排页** | `visual_check.py sbs 原稿 成品 --pages …` | 并排大图**亲眼看过**，逐块结构/意思一致 |

分工与边界（实测确认）：
- diff 阈值内 ≠ 不用看 sbs；重画页 diff 必然超标（布局本来就是新的），走 sbs 肉眼核验
- SmartArt 是 LO 回退渲染（乱叠），**布局不可比、文本可对账**——这类页走文字逐条对账（gotcha #28）
- LO 渲染不符 XML 声明值 ≠ 一定是我方错，也不 ≠ 一定不是：先对照原稿同构造再下结论，排障方法论见 gotcha #27（模型层/布局层分离 + 探针二分）
- 渲染自查抓得住：表格溢出、行高膨胀、文字回流错位、图形画错、意思层偏差（机器对账对后者全盲——gotcha #24 的五页全绿事故正是缺这道闸）

**结构对账两条路的分工**（实测确认）：原稿页本身是矢量形状群 → 用 `slide` 模式对块/带/连线；原稿页就一张位图（块数≈3）→ slide 模式无意义，改走 `ocr` 模式（原稿图 OCR 词清单对成品原生文本）。OCR 未命中逐条人工核：真缺失要补，OCR 噪声/图内装饰词进词表。

## 交付包里必须有

1. **验收对照表**：每个照画页生成"原稿块清单 vs 成品块清单 ✓/✗"对照表（structure_diff 输出整理后）写进交付说明
2. **每页处理方式声明**：逐页写明"整体沿用 / 严格重画 / 重新排版"——重画页明示请用户重点验收（沿用页有像素比对背书，重画页只有人眼能兜底）
3. **高风险页 Top-5**：按块数×连线数排序的照画页优先，明确写"建议人工过一眼的 N 页：…，其余页机器已对账"
4. **风险声明**：无渲染器时明写"本轮无渲染目检，采用结构审计"；有渲染器则写明沿用页 diff 数值 + 重画页已过并排目检
5. **密集网格密度声明**：logo 墙/证书墙类版式交付时附"密度档位可再调"（观感反馈要预留一轮校准，或直接给 2-3 档让用户选）
6. **衍生文件登记清单**：存在衍生文件（裁剪变体/虚化母题/格式转换）时列"文件名+生成方式+为何豁免哈希校验"

## 边界坦白

机器对账拦得住内容错/关系错/漏字错，**拦不住纯视觉观感**（留白失衡、配色刺眼类）。这正是 Phase 2 样张 gate 存在的原因：观感问题在样张阶段由用户拍板，不留给铺量后。治本手段仍是继承优先（见 decision-tree.md）。
