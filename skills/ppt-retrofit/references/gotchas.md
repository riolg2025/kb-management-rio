# 坑清单 — 全部踩过，逐条有事故对应

每条格式：**症状 → 根因 → 规避**。

1. **SmartArt/graphicFrame 文字不进普通文本提取 → 含 SmartArt 的页被误判"空页"整页删除**
   规避：判空页必须先跑 inventory.py 看 smartart 字段；人工复核 graphicFrame。

2. **用户报页码 ≠ 大纲页号（有删除页时错位）→ 按推算定位页全错，两轮返工**
   根因：用户说的页码是成品物理页序；删除页后成品页号 = 大纲页号 − 已删页数。
   规避：**永远从成品逐页提取 ≥20pt 标题对照大纲**，禁止推算。这是铁律 5。

3. **SIZE_MAP 反推**：要渲染 12pt 传 10，要 10pt 传 7.0–8.5，传 12 渲染成 14；14/20/26+ 原样。
   规避：写页面时先定渲染目标再反推入参；字阶表见 design-system.md。

4. **pic() 按纵横比适配居中，盒子比例与图片 aspect 不符 → 大片不对称留白（丑页主因）**
   规避：先读图片真实宽高比再定框；统一用 framed_pic（相框贴合图片）。

5. **状态文件（/tmp/ppt_dir.txt 等）随沙箱重置丢失 → 构建神秘失败**
   规避：一切路径走参数传；技能脚本已全部参数化。

6. **`python3 -I` 必加**：不加会加载 cwd 的同名模块（下载目录里被投毒的 json.py 会直接执行）。

7. **环境无渲染器（LibreOffice）→ 看不见成品**：靠几何+文本审计替代目检；交付按铁律 4 声明 + 高风险页 Top-5。

8. **文件名含"AI"等机器感字样 → 用户反感**（"用户会感觉是 AI 做的感觉不好"）。
   规避：交付前跑命名检查；用中性名（如与原稿同名或加"v6.3-优化版"类后缀，由用户定）。

9. **XML 组拷贝仅当原稿用显式 srgbClr**：schemeClr/主题色引用在新文档会被新主题污染跑色。
   规避：拷前 grep 原组 XML 的 srgbClr 密度；字体同理（显式雅黑安全，主题字体危险）。

10. **图片资产命名前缀错位 → 页内多图互相覆盖**
    事故实例：切片区间 [5:7] 截出重复前缀。规避：用"大纲页号 → 资产名"映射表生成，不用字符串切片猜。

11. **文本审计词表是生长型**：STOP/PROC 种子词表必漏新项目的版式描述词/继承图内文字 → 大量假阳性"缺失"。
    规避：审计 → 人工核对 → 扩词表循环；每项目都要养，别跳过。

12. **字体渲染环境差异**：构建机没有微软雅黑也能出文件（字体名写进 XML），但检查脚本的溢出估算按字号近似——估算非精确，旗标是"疑似"不是"确诊"，逐条人工过。

13. **大纲文件尾部附录混进最后一页审计**：`###` 级标题会关页——大纲规范里"##/### 关页"是故意的，别"修"掉。

14. **目录/文件名含空格**（如"解决方案 ppt"）：shell 命令必须加引号；交付链接里空格转 %20。

15. **深色页文字对比度**：深底上只用 LIGHT_OF 亮变体和白色；深底深字（幽灵编号除外）一律旗标。

16. **继承图页别过度包装**：壳（导语/图注/卡片）服务于图，别喧宾夺主把图挤到 1/3 以下。

17. **TIFF→PNG 转换的 sha1 必须取转换后字节**：先算 sha 再转换，manifest 登记的是 TIFF 哈希、落盘是 PNG，五件套#5 继承图哈希校验必挂"非库内"（事故：某项目证书墙 6 张扫描件全 TIFF，成品 6 图对不上库）。
    规避：extract_assets.py 已修复（转换后算 sha、去重也按最终 blob）；历史 manifest 可逐文件比对"登记 sha vs 磁盘 sha"体检。

18. **连接线照画必须提取箭头/线型/折线类型**：原稿 cxnSp 要看 headEnd/tailEnd（双箭头≠连线）、prstDash（sysDash 虚线）、prst（bentConnector2 是先横后竖的直角折线，别画成直线）。只数条数=假还原（事故：P11 六条箭头线全画成无箭头直线，用户打回）。python-pptx 侧：箭头手写 a:headEnd/a:tailEnd XML；sysDash 落盘用 MSO_LINE.SQUARE_DOT（命名不一致）；bentConnector2 用直线连接器改 prstGeom。
19. **字体遵用户约定，不从原稿主题字体推断**（事故：G2 记录"等线"（原稿主题字体），交付后用户指出此前约定微软雅黑）。字体是品牌决策，问一次记死。

20. **原稿连接线可能带 rot（竖包围盒+旋转落盘）**：bentConnector2 常以 rot=90°/270° 落盘，未读 xfrm rot 会把"横向连接线"画成"纵向贯穿线"（事故：P11 监控管理→自动化管理的横折线被画成贯穿三个节点的竖线，用户打回）。照画必读 xfrm@rot；复刻手法=竖包围盒+同角度 rot；check_geometry 已按旋转后视觉包围盒判越界。
21. **logo 墙按整图尺寸统一 ≠ 视觉统一（logo 图片自带白底）**：客户 logo 图片四周多带白底（实测白底占比中位数 67%），按整张图片统一高度时，logo 本体实际有大有小，用户一眼看出"大小不一/太小看不清"（事故：P07 137 张 logo 统一高 0.24in，本体只占中间约 1/3）。规避：①numpy 找非白像素包围盒（mask=不透明且非纯白，alpha≥40、RGB≤244），算四边裁剪比例并缓存；②python-pptx `pic.crop_left/top/right/bottom` 直接可写——PPT 原生裁剪只改显示区域，内嵌 blob 不变，继承图哈希校验不受影响；③按裁剪后本体宽高比在统一盒子内等比放大充满（add_picture 传满框 w/h 再设 crop，框比例=裁剪区域比例即无变形）：方形触高限、超宽横条触宽限，视觉大小自然一致。
22. **照画页填文本索引必须逐条对照规格存档，不能凭批注记忆写索引**（自伤事故，机器对账当场抓获）：某项目架构页中区芯片列按记忆写 T(40..44)，真实序列是 T(39..43)——整体错位一位，"业务管理"漏掉、末位误入"主机管理"，还有"资源分类管理管理"误写成页首标题文本、漏掉"持续运营"箭头组和左侧外框。靠 structure_diff 的"原稿文本未命中"计数当场暴露（未命中 1 → 逐条核对规格存档后归零）。教训：规格存档（spec_pNN.txt）既存坐标也存文本时，写码阶段每条映射都要回存档 grep 原文，别信任批注里的速记索引；这也是"机器对账 + 验收对照表"优先于肉眼自查的直接证明。
23. **嵌套组的子形状坐标是存储值≠视觉值，dump 平铺清单不可直接当绝对坐标照画**（事故：某项目 P24 按 dump 坐标重画 15 连线拓扑，位置整体错位，用户打回"如果这个图比较复杂，你应该直接沿用"）。根因：原稿拓扑在 grp3(chOff/chExt scale 1.01,0.87) 内，主机/端口标签还在更深的 grp4/grp23(scale 0.83) 内——dump 输出的是组内存储坐标，视觉坐标=逐层组变换复合后的结果。规避：①照画前先查祖先链上的 grpSpPr/xfrm 缩放，有非 1 缩放即停手；②复杂组整体 deepcopy 移植（变换随组走、渲染精确，图片按 sha1 对库重挂关系 r:embed），不要逐形状重拼。
24. **机器校验查不出"图形意思"错误——文字命中/越界/溢出/哈希全绿≠页面正确**（事故：P15/P18/P21/P24/P27 五页全绿交付，用户逐页指出"没有表达原图的意思"，其中 P24 明知照画仍错漏很多）。根因：环境无渲染器时校验体系只对账"文本在不在、框出没出界、图哈希对不对"，对形状拓扑、连线语义、视觉层次无感。规避：①复杂逻辑图/插画组的默认动作是整体沿用原稿 XML 而非重画（把"逐块重画"当例外，需逐块对照规格存档才允许）；②交付报告必须如实写明哪些页是重画（重画=高风险，需用户重点验收）、哪些是整体沿用（低风险）；③SmartArt 重画必须先从 diagrams/dataN.xml 提取 ptLst/cxnLst 真实结构，按原文逐条落形状，不许"大意重排"。
25. **渲染自查管线：环境能力必须每次实测，别信上一轮的结论**（教训：前一轮记了"无渲染器、无 root"，实际 `sudo -n whoami` 一条命令就能证伪——密码less sudo 可用，apt 可装 LibreOffice）。管线三件套：①安装 LibreOffice（`apt install libreoffice-impress`；有本地离线 deb 缓存优先用缓存免联网）②渲染 `visual_check.py render`（soffice→PDF→PyMuPDF PNG；注意 soffice 输出 PDF 用**源文件名**不是自定义名）③核验 `diff`（沿用页像素比对，阈值 6%，差异=字体替换文字回流的正常波动；热区图全红边=文件级异常，文字双影=正常）+ `sbs`（重画页并排大图，必须亲眼看过再交付）。渲染器对 SmartArt 是回退渲染（乱叠布局），但恰好可用来核对提取的 SmartArt 文本内容。链路依赖：poppler/PyMuPDF/Noto CJK 基础镜像已带，只需补 LibreOffice。
26. **表格空单元格不得写无文本 run（`<a:t/>`）——LibreOffice 把所在行撑高约 2 倍**（事故：33 行×8 列表只显示 ~20 行、行高 0.28 vs 声明 0.139、表格溢出裁剪；PowerPoint 渲染正常，更隐蔽，只有实渲自查能抓）。根因：python-pptx 给单元格写空字符串会产生 `<a:r><a:rPr/><a:t/></a:r>`，LO 布局引擎把含此 run 的行高撑到约 2×声明值。原稿惯例=空单元格只写 pPr+endParaRPr 段落（无 run）。规避：①表格构建循环后统一清除：`for t in tb._tbl.iter(qn("a:t")):` 若 `not t.text` 则删其父 run——**判断必须用 `not t.text`**，自闭合 `<a:t/>` 在 lxml 里 text=None，`==""` 匹配不到 0 个；②helper 已进 deck_lib 模板 `clean_empty_runs()`；③密表规范（margin_top/bottom=0、marL/R≈13716、endParaRPr 同字号）同见 #29。
27. **LibreOffice 渲染不符声明值时：布局层与模型层分开查，责任构造用探针二分定位**（事故：P39 行高膨胀排查 20+ 轮才收口）。方法：①先证模型层无辜——soffice 转 fodp 看声明值是否原样（模型对、渲染错 → 问题在布局引擎对某构造敏感）；②把问题形状 deepcopy 进空白 Presentation **逐项变异**（删合并/删边框/换锚点/删行区间/器官移植：外壳与内容互换），每轮独立 profile 渲染，二分锁责任；③行高实测两条路：`pdftotext -bbox` 链式解（anchor=ctr 时相邻行文字 y 差=(hᵢ+hᵢ₊₁)/2 递推）、光栅边界检测（灰度跳变+最小间隔去重）；④**反转视角最快**：原稿同构造在 LO 渲染正常 → 缺陷必在我方产物，逐项 diff 两边 XML（本事故最终靠"原稿空单元格无 run"锁定，见 #26）。别把 LO 伪影误判为"固有现象"——先对照原稿同构造再下结论。
28. **SmartArt 证据有三层，以哪层为准要逐页判断**：①数据模型 `diagrams/dataN.xml`（ptLst/cxnLst，作者最终意图）；②渲染缓存 `diagrams/drawingN.xml` + slide 内嵌缓存图（用户打开时**实际看到**的画面）；③LO 回退渲染（乱叠但文本可对账）。两层可能不一致，方向不定：P34 缓存显示四象限（旧版遗留）、数据模型是三域树 → 以模型重画；P33 数据模型的应用图谱树被缓存图盖住不显示 → 按缓存原位补画。规避：重画 SmartArt 前先比对两层的节点集合，不一致→带着具体差异问用户或按"用户看到什么"决策；含 SmartArt 页做文本审计时**缓存文本也要包进来**（独立文件，普通提取会漏，P33 的 7 条报警文本差点丢）。
29. **python-pptx/XML 边界速记（全片重建实测合集）**：graphicFrame 的变换是 **p:xfrm**（子元素 off/ext 才是 a: 命名空间）；`gf.table` 属性不存在，用 `next(sh.table for sh in slide.shapes if sh.has_table)`；inventory.json 顶层是 dict（`inv["slides"][37]["texts"]`），**文本索引含表格单元格**——照画页取页题别取到表头（事故：P39 页题误取表头文字）；原生荧光高亮=手写 `<a:highlight><a:srgbClr val="FFFF00"/></a:highlight>` 进 rPr（python-pptx 无 API），LO/PPT 两边都渲染；密表（5/4pt 级）规范=margin_top/bottom=0 + marL/R≈13716 + anchor ctr + endParaRPr 同字号 + 原稿 `a:tr h="0"` 的行显式取小值（如 0.14）消除渲染器歧义；soffice 批量排障必须每次独立 `-env:UserInstallation`（profile 锁坏=Unknown IO error），**XML 改坏时 soffice 静默输出 ~1.4KB 空 PDF**——转换前先 python-pptx 重开自检形状数（visual_check 已内置该拦截）。
